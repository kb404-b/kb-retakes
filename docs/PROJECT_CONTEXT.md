## Карта файлов

В исходном репозитории три файла:

- `index.html` — вся страница: стили, разметка, шифротекст, расчёты и взаимодействия.
- `.nojekyll` — служебный маркер для GitHub Pages.

При подготовке к Codex добавлены `AGENTS.md`, `README.md`, этот документ
и `.gitignore`. Прикладной код и зашифрованные данные не изменены.

## Устройство index.html

Ориентироваться по именам блоков, поскольку номера строк изменятся при правках:

- `window.__ENC` — JSON с полями `v`, `kdf`, `it`, `salt`, `iv`, `ct`.
  `ct` содержит шифротекст, а не открытые записи.
- `window.dash` — небольшой реестр наборов данных и вычислений:
  `data`, `calc`, `onData`, `setLink`.
- `window.__unlock(data)` / `window.__lock()` — управление данными в памяти.
- `dash.calc('kpi', ...)` — показатели по сочетаниям глобальных фильтров.
- `G`, `SJ`, `ST`, `DF` — состояние общих фильтров и поиска по вкладкам.
- `scoped()` — отбор задолженностей и группировка по ФИО.
- `draw()`, `drawLorenz()`, `drawHeat()` и связанные функции — таблицы и диаграммы.
- Последний скрипт, начиная с `gate-form`, — нормализация ключа, расшифровка и вход.

Сборщика, package.json, сервера API, базы данных, настроенного линтера,
автоматических тестов и CI в исходной версии нет.
Внешние ресурсы: D3 7.8.5 с cdnjs; IBM Plex Sans и Source Serif 4 из Google Fonts.
Текущий дизайн отличается от фирменного стиля СПбГУТ; ребрендинг не выполнялся.

## Данные и доступ

Ключ преобразуется через PBKDF2-SHA256, 600 000 итераций, в ключ AES-GCM 256 бит.
Расшифровка происходит через Web Crypto в браузере. Поля salt и iv передаются
внутри HTML. Токен нормализуется в верхний регистр и четыре группы символов.
Вход сохраняет ключ в `sessionStorage` под именем `v2-token`.
Отдельной серверной авторизации и управления пользователями нет.

Наборы данных:

| Набор | Содержание |
| --- | --- |
| `debts` | `id`, `student`, `group`, `bk`, `transfer`, `expl`, `reason`, `control`, `subject`, `sem`, `course` |
| `students` | `student`, `group`, `bk`, `transfer`, `expl`, `reason`, `debts`, `exams`, `credits`, `projects`, `sem_from`, `sem_to`, `form`, `bucket` |
| `closed` | `student`, `group`, `subjects`, `form_status` |
| `kpi` | Вычисляется из `debts`; не является отдельной загруженной ведомостью |

Основной показатель студентов вычисляется по уникальному полю `student` в
отобранных задолженностях. При расширении импорта проверить полных тёзок и
согласовать стабильный идентификатор. Поле `course` в исходном срезе равно
`ceil(sem / 2)` для всех долгов и означает курс возникновения задолженности.

На странице указаны ведомость от 23.10.2026 и ответы формы 12–15.10.
Оригиналы и полнота этих источников при переносе не проверялись.
Четыре записи `closed` — кандидаты на сверку, а не подтверждённое закрытие долгов.

## Проверенная исходная точка

2 ноября 2026 года опубликованный сайт открыт в Chromium с предоставленным
пользователем ключом. Проверены только сценарии, перечисленные ниже.
Данные — исторический срез страницы на 23.10.2026, а не текущая ведомость.

- Разблокировка проходит; D3 загружается.
- Все пять вкладок открываются: обзор, дисциплины, группы, студенты, задолженности.
- Показаны 137 студентов, 590 задолженностей, 28 групп и 77 сочетаний дисциплины
  и семестра. Называть последнее число количеством уникальных дисциплин нельзя.
- Фильтр первого доступного курса даёт 59 студентов и 248 задолженностей;
  сброс возвращает 137 и 590.
- Поиск без совпадений показывает пустое состояние; сброс возвращает 590 записей.
- Строка студента раскрывает детали по семестрам.
- Сортировка 137 студентов по числу долгов проверена в обоих направлениях.
- Блокировка возвращает форму входа и удаляет ключ из `sessionStorage`;
  неверный ключ оставляет приложение закрытым и показывает ошибку.
- Локальный HTTP-сервер запускается указанной в README командой. В браузере
  открывается форма входа, доступен Web Crypto и загружается D3. Локальная
  аутентификация отдельно не повторялась: вход проверен на опубликованном сайте.
- HTML опубликованного сайта совпадает с локальным исходником по SHA-256:
  `3e348006b49eb73aeeab4b72a3ee32b0511047ef5091ee1e10f0f89ffee667df`.
- Четыре встроенных JavaScript-блока проходят проверку синтаксиса Node.js;
  проверены формат шифрованного контейнера и ссылки в новой документации.
- Визуально проверена карточка основного графика; это не полная проверка
  всех экранов и размеров окна. Снимок без ФИО хранится в игнорируемом `output/`.
- В консоли зафиксирован HTTP 404 для отсутствующего `favicon.ico`.

Это техническая проверка страницы, а не сверка ведомостей или подтверждение
учебных статусов. Воспроизводимый импорт, настройки публикации Pages и отправка
изменений на GitHub на этом этапе не проверены.

## Дальнейшая работа

Можно сразу ставить задачи на фильтры, представление данных и расчёты.
Для регулярного обновления ведомостей отдельной задачей потребуется конвейер:
импорт → нормализация и сопоставление → контрольные суммы показателей →
шифрование → локальная проверка → публикация.
Это предложение следующего этапа, а не уже реализованная функция.

На дату переноса подключённый GitHub-коннектор даёт `pull: true`, `push: false`.
Локальная авторизация `gh` недействительна. Чтение и локальный Git работают;
для публикации потребуется восстановить доступ с правом записи. Настройки
боевого сайта при переносе не менялись.
